# LLMOS Project — Directory Guide

**Read `WHAT_THIS_IS_BUILT_ON.md` first** — at the actual project root,
not nested here. It names what this project can't enforce, and what
actually does.

One rule decides where everything below lives:

**Is this actively maintained, or is it archived history?**
Then, if actively maintained: **is it hand-authored, generated by a
tool, or narrative documentation?**

That's the whole taxonomy. Seven folders, no deeper nesting than
necessary.

```
socrates_llmos/
├── kernel/          hand-maintained behavioral spec — edit these directly
├── llmos_toolkit/     the Python package — code, not prose
├── docs/             narrative documentation — README, manuals, handoff summary
├── state/            audit/integrity artifacts — pins, ledgers, drift baselines
├── rag/              retrieval artifacts — index db, generated handoff pointer doc
├── projects/          things built USING the kernel+toolkit
└── reference/         archived history — read for ideas, don't build on directly
```

## kernel/

The canonical, currently-in-force behavioral spec. Seven substantive files, plus LICENSE:
- `HCF_LLMOS_Kernel_v1.3.6-C.md` — the methodology itself
- `SEMANTIC_DRIFT_POLICY.md` — companion policy for meaning-drift during edits
- `UNIFIED_BEHAVIORAL_OUTPUT_PROTOCOL_v2.md` — reasoning-process and output-shape rules
- `WELLBEING_FLAG_HANDLING_ADDENDUM.md` — how an instance handles a
  noticed wellbeing concern (separate from loop detection — different
  failure mode, different mechanism)
- `ARTIFACT_DELTA_LOOP_DETECTION_POLICY.md` — detects a stalled work
  loop from whether a real artifact changed, not from text variance
- `GENERIC_TASK_EXECUTION_TEMPLATE.md` — LLM-agnostic proceed/ask/confirm/report pattern for any task
- `DECISION_FINALITY_POLICY.md` — when a decision counts as settled
  without multi-instance re-confirmation, and which categories always
  stay on slower deliberate review regardless
- `LICENSE`

**As of 2026-08-14, all arrow-chain and inequality-symbol shorthand has
been removed from these files** (e.g. "A → B", "X ≠ Y", Compact
Operating Cards). That shape was flagged as pattern-matching to
command/runtime syntax by at least one host model, independent of
surrounding disclaimer prose — a cross-model trust risk. Every rule now
states in a plain sentence as its sole operative form. Single-letter
evidence tags (V/I/A/U, H/O/E/I/S/U) were kept — classification labels,
not command sequences, judged lower risk. See each file's own Change
Log section for the full accounting.

These are the only files in this whole tree you should be routinely
hand-editing. Everything else either generates from these, references
them, or is history that led to them.

## llmos_toolkit/

The `llmos_toolkit` Python package — `core/` (registry, plugin loader,
security, CLI, centralized path resolution), `plugins/` (13 as of
2026-08-14: growth_budget, drift_check, claim_flag, token_audit,
adaptive_drift_logger, sync, git_sync, secret_scanner, handoff_rag,
audit_all, session_close, ledger_compact, example_hello), and `hooks/`
(git pre-commit template). Its own `README.md` and `HOW_TO_USE_THIS.md`
inside this folder have the full command reference — not duplicated
here.

**The folder must be named exactly `llmos_toolkit`** — `python -m
llmos_toolkit` resolves that name to this directory, and the plugins
import `from llmos_toolkit.core.registry import registry` directly.
Renaming it breaks both.

Install and run:
```
pip install -e . --break-system-packages --no-build-isolation
llmos --list-commands
```
All generated state resolves through `llmos_toolkit/core/paths.py` —
run commands from anywhere in the project; you no longer need to `cd
state` first. Every path constant that once hardcoded a relative
filename (a real, recurring bug found and fixed across 6 separate
files this session) now routes through `paths.get_state_path()` or
`paths.get_rag_path()`.

## docs/

Narrative documentation — README (this file), `MANUAL_START_HERE.md`,
`NOTICE.md`, `PROJECT_HANDOFF_SUMMARY.md`, `INSTANCE_ORIENTATION_SEQUENCE.md`,
`CHANGELOG.md`. New readmes, manuals, and changelogs belong here, not
scattered at project root.

## state/

Audit and integrity artifacts only: `growth_ledger.jsonl`,
`kernel_pins.json`, `.drift_state.json`, `drift_audit.jsonl`,
`token_ledger.jsonl`, `drift_rules.json`. Everything here is
tool-generated — never hand-edit, safe to inspect but not to delete
casually now that `ledger-compact` gives ledgers real permanent history
via skeleton summaries rather than raw-only growth.

This folder is kept separate from `rag/` deliberately: a full RAG
index rebuild should never touch audit history, and vice versa.

## rag/

Retrieval artifacts: `handoff_rag.db` (the TF-IDF index) and
`SESSION_HANDOFF.md` (generated pointer doc, regenerated automatically
by `session-close`). Both regenerate in seconds via `rag-index` /
`rag-handoff` — never worth treating as precious, unlike `state/`.

## projects/

Actual work-product that *uses* the kernel/toolkit — not part of the
LLMOS infrastructure itself.
- `depolarize/` — the anti-bias/de-escalation prompt, its requirements
  ledger, maintenance toolkit, and changelog
- `threat_response/` — the draft corrective-action reference guide

Future unrelated projects go here as new sibling folders, each self-
contained. This is the folder that grows over time; the infrastructure
folders should stay close to their current size.

## reference/

Archived, not actively maintained. Two subfolders:

- **`llmos_architecture_history/`** — superseded kernel/adapter
  versions, including `HCF_LLMOS_Compatibility_Adapter_v1_3.md` and
  `HCF_LLMOS_Precision_Refactor_Calibration_v1.md` — both confirmed
  during this session's equivalence spot-check to hold real content
  from the kernel's predecessor that looked missing but was actually
  correctly kept standalone.
- **`pilot_and_research/`** — the shared-substrate pilot design, the
  mathematical-gateway research conversation, process manuals, the
  boundary report, cognitive-state-intervention notes, and the (unrun)
  pilot harness code.

Nothing in `reference/` needs a decision. It sits here until something
concrete in `projects/` or `kernel/` actually needs to draw on it.

## What's deliberately NOT in this tree

`AI-Coordination-070526.zip` was found in the upload directory during
the original reorganization but never discussed in the conversation
that produced this structure, and contains a file that appears to hold
real credentials (`DO-NOT-SYNC/activepieces-secrets.md`). It was
excluded entirely, not filed into `reference/`.
